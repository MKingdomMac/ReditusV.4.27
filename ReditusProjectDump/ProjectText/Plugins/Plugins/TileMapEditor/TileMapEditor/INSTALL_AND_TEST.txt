Snapped unbounded terrain merge (v1.2.33)
-----------------------------------------
This focused revision starts again from the user-checked v1.2.31 source. It
replaces the rejected v1.2.32 exact-alignment merge with a forgiving snapped
merge. Continuous-terrain geometry, ramp geometry, horizontal-cut geometry,
collision, and baking code are unchanged.

What changed:
- The target is treated as an unlimited 3D integer lattice. It has no finite
  X, Y, Z, occupied-area, actor-bounds, or current-chunk boundary.
- A source may be completely disconnected, far beyond the target's occupied
  area, above it, below it, or in negative grid coordinates.
- Each source block center is transformed through world space and rounded to
  the nearest target grid-cell center. Exact actor-origin alignment is no
  longer required.
- The source still requires the same Grid Size, actor scale, block mesh, and
  ordered tile palette. It may use an exact 0/90/180/270-degree relative yaw.
- Existing target cells always win. They no longer cancel the complete merge,
  even when their current auto-tile visual differs from the source.
- When selected sources overlap each other, the first deterministically sorted
  source supplies the cell and later duplicate source cells are skipped.
- Added blocks retain tile type, ramp/diagonal segment identity, and corrected
  quarter-turn rotation. Auto-tiling is re-evaluated only around the joined
  boundary.
- The target is modified once and only dirty plus neighboring chunks rebuild.
  Source actors are never moved, edited, hidden, or deleted.
- The complete target mutation is one Undo/Redo transaction.
- The success message reports added blocks, retained target overlaps, skipped
  source overlaps, and the largest physical snap correction.

The snap is for whole occupied cells. A half-height ramp surface remains inside
its copied cells because its tile metadata is retained. This does not add
half-cell occupancy; small half-height ledges and irregular rock protrusions
belong to the planned separate terrain-detail module layer.

Exact merge workflow:
1. Select the terrain actor that should receive the copied block data.
2. In Tile Map mode, under Snapped Terrain Merge, click
   Set Selected as Merge Target.
3. Duplicate one or more compatible terrain actors normally.
4. Move the copies approximately to the desired world position and elevation.
   They do not need to touch or overlap the target's current terrain.
5. Select the copied source actors in the World Outliner. The stored target may
   also remain selected.
6. Click Snap + Merge Selected.
7. Read the added/overlap/snap report, hide the source actors, and inspect the
   target. Delete sources only after approval.

Ramp contacts use ground treatment (v1.2.31)
------------------------------------------------
This focused revision removes the cliff-foot material mask wherever an ordinary
continuous wall or lower ground contact involves a valid continuous Vertical
Ramp. It starts from the user-verified v1.2.30 source.

Diagnosis:
- The ramp generator itself never emitted the cliff-foot mask.
- The ordinary cliff generator enabled its foot mask whenever continuous
  support existed on both sides of a wall.
- A lone ramp could satisfy that ordinary support test at its upper contact.
  Two side-by-side ramps suppress their shared wall, so the same mask was not
  generated there. This caused the layout-dependent band in the screenshot.

What changed:
- Ordinary top-surface contact detection now rejects Cliff Foot Blend when the
  adjacent support or stacked contact is a continuous Vertical Ramp.

Color RGB value into the material. Read only R through a OneMinus node.

Master-material first hookup:
1. Add a Vertex Color node.
2. Connect its R output to a OneMinus node.
3. Use that result as the Alpha of a Lerp.
4. Connect the existing terrain result to A and a temporary bright red color to
   B. Compile and confirm that only the wall/ground contact band turns red.
5. Replace the red debug color with the desired soil, moss, darkening, or
   cliff-foot material result.

When using Material Attributes, use the same mask as the Alpha of Blend Material
Attributes instead of a color Lerp. After the basic band is visible, world-space
noise can perturb the mask inside the master material without changing mesh
topology.

New selected-actor controls under Tile Map > Continuous Terrain:
- Cliff Foot Blend Width: horizontal ground fade, default 12.
- Cliff Foot Blend Height: vertical cliff fade, default 10.

Setting both controls to 0 leaves all generated vertex colors white and disables
the feature. Optimized static-mesh baking already copies procedural vertex
colors, so the same master-material blend is preserved after baking.

No slant, diagonal-cut, cursor, painting, undo/redo, collision, HISM fallback,
material assignment, cliff-lip shape, or occupied-block data logic was changed.

Cliff-edge stacked-corner support (v1.2.14)
------------------------------------------------
This revision fixes the small triangular opening that could appear where a
rounded block corner is stacked directly above the chamfered or wavy boundary
of its supporting layer. The existing rounded inner arc is unchanged. Its
outer transition vertex now follows the visible support surface's actual
height, while the adjacent horizontal waviness fades back to their shared grid
corner. This keeps the transition fan valid and makes the two surfaces meet.

The v1.2.12 corner-patch triangulation is preserved. Interior stacks still use
the original flat transition, and a zero-irregularity edge still follows the
straight v1.2.12 horizontal path except for the existing physical chamfer.

Focused verification:
- Place a block above an interior block: the transition remains flat and full.
- Place a block above a straight exposed cliff edge: no triangular opening.
- Repeat at all four cliff-corner rotations and at a three-block concave notch.
- Set Cliff Edge Irregularity to 0 and then above 0; both remain watertight.
- Check collision from above and beside the repaired transition.

No slant, diagonal-cut, editor-tool, undo/redo, material, HISM fallback, cursor,
or optimized static-mesh baking logic was changed.

Subtle deterministic cliff-lip waviness (v1.2.13)
-------------------------------------------------
This revision adds physical horizontal irregularity only to the narrow exposed
top lip. The flat ground interior keeps its original Z plane. Rounded corner
arcs remain clean, and the waviness fades into them instead of producing spikes.
The main cliff face keeps its original straight footprint; only a shallow upper
transition connects it to the irregular rim.

Recommended first test values on the selected terrain actor:
- Chamfer Subdivisions Per Tile: 8
- Chamfer Width: 10
- Chamfer Depth: 5
- Cliff Edge Irregularity: 4
- Cliff Edge Wavelength: 65
- Cliff Corner Radius: 10

Existing actors retain their saved Chamfer Width and Chamfer Depth. If the old
30/10 values are still displayed, enter 10/5 manually or click their reset
arrows. New actors use 10/5 by default.

The edge curve is sampled from world position, wall direction, and terrain
layer, so adjoining tiles and chunks calculate identical shared lip vertices.
Setting Cliff Edge Irregularity to 0 restores the v1.2.12 straight-edge path.
Slants and diagonal cuts deliberately remain on their existing modular path.

Supported convex-corner transition caps (v1.2.12)
-------------------------------------------------
This revision fixes the small white triangular opening that could appear at the
bottom of a rounded cliff corner resting on a wider supporting terrain layer.
The narrow cutout is now triangulated from the actual square corner along each
rounded-arc segment. It no longer uses a center fan outside the concave patch.
The same correction is used for downward-facing stack transitions.

No cliff-wall, flat-top, chamfer, slant, editor-tool, collision, material,
undo/redo, HISM fallback, or optimized-baking behavior was otherwise changed.

Declaration-placement correction (v1.2.11)
-------------------------------------------
This revision fixes the v1.2.10 compile error shown by Visual Studio. The
ChamferDepth local is now declared exactly once in GetContinuousTopSurfaceZ
and exactly once in BuildContinuousChunk, before either function uses it.
Terrain geometry and editor behavior are otherwise unchanged from v1.2.10.

Physical cliff-corner fillets (v1.2.10)
----------------------------------------
This revision removes the remaining sharp vertical cliff lines. Long cliff
spans remain planar and mostly vertical, but their endpoints are physically
trimmed and joined by narrow curved geometry.

- Convex outside corners receive a rounded silhouette.
- Concave notches, including a 2x2 group with one deleted block, receive an
  inward rounded fillet.
- Flat top interiors remain exactly on their original Z plane.
- The rounded top boundary, wall strip, floating underside, and stack
  transition patches share the same corner radius so they remain supported.

Set Cliff Corner Radius to 10 for the first test. Chamfer Subdivisions Per Tile
also controls corner smoothness; 8 is the normal default and 16 is a denser
visual test. This does not modify ramps or diagonal cuts yet.

Continuous face-winding correction (from v1.2.9)
------------------------------------------------
This revision changes only the triangle winding of the continuous procedural
terrain. It now follows the same proven 0,2,1 front-face convention used by the
original v1.2.6 optimized static-mesh builder. Top surfaces, cliff walls,
chamfer strips, and exposed undersides therefore render from their outward side.

The chamfer dimensions and terrain-shaping rules from v1.2.8 are unchanged.
The modular/HISM fallback, slants, cursor tools, collision, materials, undo/redo,
and optimized mesh baking are unchanged.

Exposed top-edge chamfer prototype (from v1.2.8)
------------------------------------------------
This revision replaces v1.2.7's incorrect full-height boundary waviness with a
physical chamfer applied only where flat ground drops into an exposed cliff.
It does not replace or delete the original modular/HISM renderer.

1. Create or select the TileMap_Terrain actor.
2. In Details, open Tile Map > Continuous Terrain.
3. Enable Use Continuous Terrain Prototype.
4. Leave Chamfer Subdivisions at 8, Chamfer Width at 14, and Chamfer Depth at
   8 for the first test.
5. Click Create Test Grid.

Expected result:
- Flat top faces are visible when viewed from above.
- Cliff and chamfer faces are visible from outside the terrain, not from inside.
- Long cliff walls stay flat while their vertical endpoints become rounded.
- A deleted corner produces a curved inward notch instead of a sharp 90-degree
  vertical seam.
- Adjacent ordinary blocks read as one continuous terrain mass with no seams.
- Buried faces and internal cliff faces are not generated.
- The interior ground remains exactly on its 100-unit Z plane.
- Only a narrow band beside an exposed top cliff edge slopes downward.
- The cliff wall beneath that band is a straight planar vertical face.
- The cliff wall is never made wavy or pushed sideways.
- A 2x2 group with one corner block removed produces a rounded chamfer
  transition where the remaining three top surfaces meet the missing corner.
- Stacked terrain has no internal faces between its occupied blocks.
- Floating blocks above Z=0 receive exposed underside geometry for overpasses.
- Chunk boundaries calculate identical chamfer heights, with no gaps.
- Collision, cursor editing, undo/redo, materials, and optimized baking remain
  active in this mode.

Disable Use Continuous Terrain Prototype at any time to restore the complete
v1.2.6 chunked HISM rendering path.

Scope of this prototype:
- Existing Ramp and Diagonal Edge tiles deliberately remain on their original
  modular mesh path. Their geometry and editor behavior were not changed.
- Slant-to-chamfer stitching is deliberately deferred until the ordinary
  flat/stacked chamfer is visually and functionally approved.

Shared terrain material
-----------------------
1. Select the TileMap_Terrain actor.
2. In Details, open Tile Map > Rendering.
3. Assign MI_Reditus_Terrain to Default Terrain Material.

When assigned, this shared material intentionally takes precedence over the
default cube material and palette material overrides. It is automatically used
by flat blocks, generated slants, rebuilt HISM chunks, and optimized baked
meshes. Clear the property to return to individual mesh/palette materials.

Slants
------
- Ramp converts a complete run of existing blocks into one continuous wedge
  inside those cells. It rises from the bottom of the first selected block to
  the top of the last block; it does not add slope geometry above full cubes.
- Choose +X, +Y, -X, or -Y before applying. The complete run is rotated for
  you; individual Rotate clicks are no longer required.
- The requested angle is snapped to the nearest grid-compatible run from one
  through eight tiles. The mode panel displays the tile count and actual angle.
- The clicked block is the low end. The rise continues in the chosen direction.
- Every block needed by the displayed run length must already exist at the
  clicked elevation. If any block is missing, the preview is red and no partial
  ramp is applied.
- Diagonal Edge changes the selected block into a diagonal boundary and removes
  only the nearest column behind the selected cut direction, including blocks
  stacked at or above the selected elevation. It never continues deleting
  through another row or column of the map.
- Slant Angle accepts 5 through 45 degrees.
- The generated slant uses the material of the currently selected Active Tile.
- Apply Slant automatically changes all matching ramp segments in one action.
- Paint / Replace Tile restores another palette tile.
- Delete Block removes the block completely.
- Generated static meshes are reused from /Game/TileMapGenerated.

Elevation-aware auto tiling
---------------------------
Each Tile Palette entry now has:
- Auto Tile Set
- Auto Shape

Give related modular assets the same non-empty Auto Tile Set, such as Grass.
Assign each mesh its role: Flat, Edge, Outer Corner, Inner Corner, Cliff,
Pass / Bridge, Peninsula, or Island. Painting any member of the set selects the
correct available sibling variant and rotation based on nearby occupied cells.

Base mesh orientation assumptions before automatic 90-degree rotation:
- Edge and Cliff face/open toward +X.
- Outer Corner is open toward +X and +Y.
- Inner Corner's missing diagonal is +X and +Y.
- Pass / Bridge is open on +X and -X.
- Peninsula is closed toward -Y.

If a requested shape is absent, the resolver uses the set's Manual / Any entry
when available. If neither exists, it safely keeps the current tile.

Efficiency
----------
- Terrain remains chunked and rendered with HISM components.
- Edits resolve only the affected cell and immediate neighboring elevations.
- Only touched chunks rebuild.
- Generated slant meshes are cached and shared instead of creating one mesh per
  placed block.
- A multi-tile ramp updates tile type and absolute direction as one batch, then
  rebuilds each affected HISM chunk only once.
- Each mouse stroke remains one native Unreal Undo/Redo transaction.

Primary fixes in this package
-----------------------------
- Added physical convex and concave vertical cliff-corner fillets. This changes
  the silhouette; it is not a smooth-normal-only lighting trick.
- Added matching top, underside, and stacked transition geometry around rounded
  corners so collision and static-mesh baking receive the same surface.
- Corrected reversed triangle winding in every continuous procedural surface:
  flat tops, exposed cliff walls, chamfer strips, and exposed undersides.

- Restored the original working horizontal diagonal orientation. New V4

- Moved ramp surfaces inside the selected cells so the original cubes are

- Diagonal Edge removes only its nearest cut-side neighbor and that neighbor's

- Aligned each diagonal boundary mesh with its selected cut direction.
- Replaced the repeated one-cube wedge with closed, height-matched ramp segment

- Corrected the Diagonal Edge top-face winding so the cap is visible from above.

- Restored the missing closing brace in FTileMapEdMode::HandleClick. That brace
