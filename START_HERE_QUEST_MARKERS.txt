REDITUS QUEST MARKERS — 2.2.0 — UE4.27

INSTALL THIS UPDATE
1. Close Unreal. Extract/merge BOTH folders from this ZIP into your project:
     Plugins/ReditusQuestNPC
     Plugins/MinimapPlugin
   The MinimapPlugin folder adds three source files to your existing plugin.
   Keep its existing source, .uplugin, content and assets. Do not replace that
   whole folder with only these additions.
2. Build Development Editor / Win64 with Unreal closed. Reopen after success.
   No PowerShell script. No need to recreate your working NPC or redo the
   quest journal integration. Native reflected types require a cold build.

ONE TEST NPC
1. Open DT_Quests, select a valid quest row and set Is Main Quest:
     CHECKED   = ! (main quest, including turn-in)
     UNCHECKED = ? (side quest, including turn-in)
2. On your NPC's DT_QuestNPCs definition, set Quest:
     Data Table = DT_Quests
     Row Name   = that quest's row name
   If you use Inline Definition instead, leave Definition Row's Row Name
   unselected and assign Inline Definition > Quest. A selected NPC row takes
   precedence over inline settings. Merely assigning dialogue is not a quest.
3. Press Play. The quest's Markers defaults show both the minimap icon and a
   screen-space marker above the NPC's flipbook. No texture, widget or marker
   type needs to be assigned on the NPC. Existing NPC assets work with this.

QUEST-OWNED VISIBILITY
DT_Quests > Markers contains:
  Show When Available       default true
  Show While Active         default true
  Show When Ready To Turn In default true
  Show On Minimap           default true
  Show Overhead             default true
  Show Objective Destinations default true
Completed, failed, unknown and prerequisite-locked quests hide markers.
Changing quest progress or importing quest state refreshes markers immediately;
the existing half-second refresh also handles late minimap/player startup.

For an active stage, Stages > NPC Marker Visibility can be Inherit Quest,
Show or Hide. For example, hide the giver while the player travels to another
destination; show it again in a return-to-NPC stage. This never changes ! to ?.

Destination actors still choose Quest / Stage ID / Objective ID to identify
where to guide the player. DT_Quests supplies main/side type, and its Markers
settings can disable destinations. Destination markers only show for matching
active, unfinished objectives; they never complete an objective by showing it.
NPC marker/dialogue selection remain separate: Extra Rules can pick dialogue
for another quest without silently changing the attached quest's marker.

NO CHARACTER ICON OVERRIDES
The previous NPC/objective Marker Kind, Custom Marker Icon, visibility flags,
Main Quest Icon and Side Quest Icon are retired and hidden from Details.
Old serialized fields remain for Blueprint compatibility but do not affect
markers. The quest owns classification/visibility; MinimapPlugin owns artwork,
colour, size, overhead offset and minimap-edge display.
Default pixel !/? textures are generated at runtime. They need no asset import.

OPTIONAL GLOBAL STYLE (not required for setup)
Use Config/DefaultGame.ini, section:
  [/Script/MinimapPlugin.MapQuestMarkerStyle]
Example settings:
  MinimapSize=26.0
  OverheadSize=(X=32.0,Y=40.0)
  OverheadOffset=(X=0.0,Y=0.0,Z=24.0)
  MainQuestColor=(R=1.0,G=0.72,B=0.2,A=1.0)
  SideQuestColor=(R=0.35,G=0.85,B=1.0,A=1.0)
  EdgeMarkers=True
Optional MainExclamationIcon / SideQuestionIcon accept texture soft paths.
If used, reference those textures from a cooked asset or add their directory
to your packaging cook settings. The generated defaults need no cook entries.

IF A MARKER IS MISSING
- Verify both the NPC definition row and its Quest's table AND Row Name.
- Test a valid quest with no prerequisites, in a fresh Play session.
- Completed/failed/locked quests intentionally do not show; check Read Quest.
- Check DT_Quests > Markers and the current stage's NPC Marker Visibility.
- Make sure the three MinimapPlugin files were included in the cold build.
- Your existing minimap still needs its normal player/view/widget setup;
  map fog/layer filtering still applies. This update retries icon registration
  if the game state's map tracker was not ready at NPC BeginPlay.

PROJECT TEST AFTER BUILD
Available main (!), available side (?), active, ready to turn in, completed;
stage Hide/Show; save/load completed; permanent NPC removal; a dialogue-only
NPC without a quest; a destination objective; level reload; existing dialogue.
Check both displays. Switching main/side changes both; turn-in never swaps them.

Offline adapter/policy/glyph checks are included. Unreal compilation, UHT and
actual rendering have NOT been run in this workspace.
